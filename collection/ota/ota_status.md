# OTA 状态管理代码逻辑总结

> 本文只描述代码「做什么、怎么做」，不涉及问题评判。

## 一、总体模型

把一片专留的 Flash 扇区当作 **OTA 状态的追加式日志（append-only log）**：

- 状态**不原地改写**，每次升级/翻转都**新写一个字**到下一个空闲位置。
- 利用 Flash 物理特性「只能把位从 1 写成 0、不能从 0 写回 1」，以 `0xFFFFFFFF` 作为「未写过」的空闲标记。
- 读取时顺序扫描，找到第一个空闲字，其前的有效字即「当前最新状态」。

## 二、存储布局

| 项 | 值 |
|----|-----|
| 扇区地址 | `0x080F0000`（裸扇区，专供 OTA 状态） |
| 扇区大小 | `2048` 字节（2KB） |
| 字宽 | `4` 字节（32 位系统单次写） |
| 可容纳字数 | `2048 / 4 = 512` 个字 |

每个 32-bit 字 = 一条历史状态记录；整页构成一条状态链。

## 三、状态定义

枚举 `OtaStatus_t`，每个值语义如下：

- `OTA_STATUS_IDLE = 0xFFFFFFFF`：擦除后的初始态，同时是「空闲字」的标记（不主动写入日志）。
- `OTA_STATUS_DOWNLOADING = 0xAAAA5555`：正在下载固件。
- `OTA_STATUS_VERIFYING = 0x5555AAAA`：下载完成，正在校验 CRC/ECC。
- `OTA_STATUS_READY = 0x3333CCCC`：校验通过，等待重启刷写。
- `OTA_STATUS_UPGRADING = 0x00000000`：正在由 Bootloader 执行刷写。

## 四、读逻辑：OTA_Get_Current_Status()

目标：找出当前最新的 OTA 状态。

步骤：
1. 指针指向扇区首字，`current_status` 初值为 `OTA_STATUS_IDLE`。
2. 从头到尾逐字扫描（最多 512 字）：
   - 若当前字 `== 0xFFFFFFFF`：说明到了第一个未写过的空闲字，其前一个字就是最新状态；取 `ptr[i-1]`（当 `i>0`）作为结果并结束。
   - 若不是空闲字：继续往后扫。
3. 返回 `current_status`。

不变量：一旦遇到空闲字即停止，链是线性、不回跳的。

## 五、写逻辑：OTA_Update_Status()

目标：把 `set_status` 追加写入日志，**绝不原地擦除**已有记录。

步骤：
1. 指针指向扇区首字，逐字扫描：
   - 找到第一个 `== 0xFFFFFFFF` 的空闲字 `i`：
     - 调用 `HAL_Flash_Write_Word()` 把 `set_status` 写入 `addr + i*4`。
     - 硬件返回 0 → 写入成功，返回 0；否则返回 -1。
2. 若整页扫完都没有空闲字（页写满）：
   - 调用 `HAL_Flash_Erase_Page()` 整页擦除，使所有字回到 `0xFFFFFFFF`。
   - 把 `set_status` 重新写入扇区首字，返回其写入结果。

即：**常态走「追加」，只有页满才「整页擦除 + 重写」**。

## 六、关键不变式

- **空闲标记**：`0xFFFFFFFF` 表示该字可写、未被占用。
- **写单向性**：写入只清除位（1→0），故任意状态值写进 `0xFFFFFFFF` 都是合法、确定的。
- **读取边界**：扫描遇空闲字即止，最新状态恒为「最后一个有效字」。
- **追加纪律**：正常流程下不修改历史字，记录按时间顺序线性增长，直到页满触发一次压缩。

## 七、典型状态流转（调用时机）

```
IDLE ──(开始下载)──▶ DOWNLOADING
DOWNLOADING ──(下载完)──▶ VERIFYING
VERIFYING ──(CRC 通过)──▶ READY
READY ──(重启)──▶ UPGRADING
UPGRADING ──(刷写成功)──▶ IDLE（重新擦写/转下版本）
```

每次流转由 `OTA_Update_Status(下一状态)` 追加一条记录，`OTA_Get_Current_Status()`
在任意时刻都能恢复「此刻处于哪一步」。
